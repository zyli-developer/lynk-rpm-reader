# 仪表双区域转速显示设计

> 文档状态：设计基线 v0.4，互斥位置开关已进入 APK 实现。  
> 适用系统：FlymeAuto 2.5.0 当前车机版本。  
> 重要限制：Display 10 与 Display 11 已确认是两路 1920×720 外部显示通道，但它们与仪表左、右区域的对应关系尚未完成可见性验证。实现前不得硬编码左右关系，也不得用全屏 Activity 直接覆盖仪表。

## 设计目标

在不影响原车车速、挡位、告警、续航和能耗信息的前提下，将发动机实时转速增加到以下两个候选位置：

1. 左侧速度区：完整保留车速在上、功率在下的纵向结构，只在该区域最底部增加转速数值。
2. 右侧功能卡片区：在音乐、车辆属性、行程数据之外增加“转速”卡片。

两个位置都使用 `1.0 × 1000 RPM` 形式显示转速，不直接显示 `1000 RPM`。界面不显示圆盘、指针、刻度、进度条或其他形式的转速表。右侧转速数值只在用户切换到“转速”卡片后显示；切换到其他卡片时立即隐藏。APK 中提供 `关闭 / 左侧速度区 / 右侧转速卡片` 三选一开关，左、右两个位置互斥，任何时刻不得同时显示。

## 显示位置开关

- 开关采用单选状态，不使用两个可以分别开启的布尔开关。
- `关闭`：停止当前转速副屏输出，并恢复原车仪表内容。
- `左侧速度区`：仅在车速、功率纵向结构最下方显示转速；右侧转速卡片不得显示。
- `右侧转速卡片`：仅启用右侧转速卡片；左侧速度区不得显示转速。
- 从左侧切换到右侧或从右侧切换到左侧时，必须先停止旧位置，再启动新位置，不能存在两路重叠的过渡帧。
- 选择结果需要持久化；若副屏创建或切换失败，开关恢复为 `关闭`，不能显示“已开启”但实际没有输出。

## 当前依据与边界

| Evidence（依据） | Finding（结论） | Path（对设计的影响） |
|---|---|---|
| 用户提供的仪表照片 | 左侧是车速/功率区，右侧是音乐、车辆属性、行程数据切换区 | 按两个独立安全区域设计，不设计全屏仪表替代界面 |
| `dumpsys display` | 存在 Display 10、Display 11，两者均为 1920×720、外部物理显示、状态 ON | 作为待验证的两路投送通道；不直接等同于照片中的左右坐标 |
| Display 10、11 的 Android 截图为黑屏 | 原车仪表由车规图形链路或另一系统合成，普通 Android 截图无法读取最终画面 | 必须通过实车可见性测试确认通道和透明合成能力 |
| Display 3 为 520×280 的私有虚拟投影，并由地图 HUD 页面使用 | Display 3 不是照片中圈出的两个区域 | 排除 Display 3，不向其投送转速界面 |
| 当前 APK 已能读取 FlymeAuto 2.5.0 转速 | APVP 信号兼容 `0x12600596` 和 `0x12600597`，读取周期约 100 ms | 两个设计共用同一数据层，只更换仪表端渲染方式 |
| 当前转速模型 | 有效显示范围 0–8000 RPM | 显示值按 `RPM ÷ 1000` 换算并保留一位小数，范围为 `0.0–8.0` |

照片中的红圈只能用来定义视觉区域，不能作为程序最终坐标。以整个仪表内容画布为 `1.0 × 1.0` 参考，当前照片估算的安全区域如下：

| 区域 | 归一化范围（估算） | 必须保留的原车内容 |
|---|---:|---|
| 左侧速度区 | `x=0.08–0.33, y=0.15–0.81` | 车速、`km/h`、功率读数及左下告警状态 |
| 中央车辆区 | `x=0.34–0.70` | 车辆模型及车辆状态，不放置转速信息 |
| 右侧功能区 | `x=0.71–0.97, y=0.14–0.81` | 功能切换栏、当前卡片标题和必要状态 |
| 顶部保留区 | `y=0–0.13` | 温度、时间和系统状态 |
| 底部保留区 | `y=0.82–1.0` | 挡位、告警、里程、油量和电量 |

最终像素坐标必须以实车输出链路提供的实际画布和裁切参数重新标定。

## 左侧速度区方案

### 信息结构

车速仍是最高优先级信息，现有位置、字号和上下结构保持不变。功率继续位于车速下方，原有分隔关系不变。转速作为新增的第三行数据，放在整个左侧区域最底部，与功率之间保留明显间距。

```text
┌────────────────────┐
│                    │
│        0           │  原车车速，保持不变
│       km/h         │
│   ───────────      │
│        0 kW        │  原车功率，保持不变
│                    │
│  1.0 × 1000 RPM    │  1000 RPM 的显示示例
└────────────────────┘
```

### 视觉规格

| 元素 | 规格 |
|---|---|
| 转速数字 | 使用 `RPM ÷ 1000` 的结果，固定保留一位小数；例如 1000 RPM 显示为 `1.0`，850 RPM 显示为 `0.9` |
| 倍率与单位 | 数值后显示 `× 1000 RPM`；使用乘号 `×`，不使用字母 `x` 或程序运算符 `*` |
| 布局 | 在左侧区域最底部单独占一行并水平居中；不得压缩、移动或替换上方车速与功率结构 |
| 显示内容 | 只显示 `一位小数 × 1000 RPM`，不显示标题、状态文字、圆盘、指针、刻度、色带、进度条或启动扫表动画 |
| 正常颜色 | 跟随原车日/夜主题；浅色主题使用深灰文字，深色主题使用白色文字 |
| 背景 | 默认完全透明，不绘制独立卡片底色，不改变原车天空和车辆主题背景 |

### 行为约束

- 转速数字以最大 10 Hz 刷新；数值变化可做约 140 ms 的数字平滑，但不得产生回弹、闪烁、滚轮或扫表效果。
- 不允许遮挡、移动、缩小或重排车速、`km/h`、功率、警告灯和驾驶模式信息。
- 转速不可用时显示 `—.- × 1000 RPM`，不得弹窗，也不得在仪表上显示调试错误。
- 如果投送链路不支持透明合成，立即放弃本方案，不允许用不透明窗口重建或覆盖原车速度区。

## 右侧功能卡片方案

### 信息结构

在现有音乐、车辆属性、行程数据纵向功能栏中增加“转速”入口。它与现有功能使用完全相同的卡片切换逻辑：仅当用户切换到“转速”入口时显示转速卡片；切换到音乐、车辆属性或行程数据后，转速内容立即隐藏，原卡片正常显示。

```text
┌────────────────────────┐
│                   ♪    │
│                   ◇    │
│      1.0          ╱    │
│  × 1000 RPM       R    │  当前选中“转速”入口
│                        │
│                        │
└────────────────────────┘
```

### 视觉规格

| 元素 | 规格 |
|---|---|
| 主数值 | 在卡片内容区居中显示 `RPM ÷ 1000` 的结果并固定保留一位小数；数字是卡片中唯一的主要内容，但不得大于左侧车速数字 |
| 倍率与单位 | `× 1000 RPM` 放在主数值下方；与左侧使用完全相同的写法 |
| 显示内容 | 卡片内容区只显示 `一位小数 × 1000 RPM`，不显示标题、状态文案、转速表、圆盘、指针、刻度、进度条或曲线 |
| 功能图标 | 仅在右侧既有切换栏中增加一个简化的 `RPM`/字母 `R` 标识，风格与音乐、车辆、行程图标一致；不使用圆形转速表图标 |
| 背景和圆角 | 跟随原车卡片材质、透明度和圆角，不沿用主 APK 当前的深色遥测面板外观 |

### 交互规则

- 入口顺序建议为：音乐 → 车辆属性 → 行程数据 → 发动机转速。
- 通过原车方向盘按键或既有功能切换方式选择，不在仪表上增加新的触摸热区。
- 切换到转速卡片时才创建或显示转速内容；切换离开后隐藏该内容，不覆盖相邻卡片。
- 车辆重新启动后恢复原车默认卡片，不强制占用右侧区域。
- 右侧转速卡片关闭或切换后，可停止该区域的界面刷新，但不停止底层数据连接，避免再次进入时长时间等待。

## 数据状态与降级

| 状态 | 触发条件 | 左侧表现 | 右侧表现 |
|---|---|---|---|
| 初始化 | 尚未收到第一帧有效数据 | `—.- × 1000 RPM`，灰色 | 选中转速卡片时显示 `—.- × 1000 RPM` |
| 正常 | 最近 500 ms 内收到有效帧 | 显示实时的 `一位小数 × 1000 RPM` | 选中转速卡片时显示实时的 `一位小数 × 1000 RPM` |
| 短暂中断 | 500 ms–2 s 未更新 | 保留最后值并降低亮度 | 保留最后值并降低亮度，不增加状态文案 |
| 不可用 | 超过 2 s 未更新或数据通道失败 | `—.- × 1000 RPM` | 选中转速卡片时显示 `—.- × 1000 RPM` |
| 发动机停止 | 收到有效值 0 RPM | 显示 `0.0 × 1000 RPM` | 选中转速卡片时显示 `0.0 × 1000 RPM` |
| 异常数值 | 非有限值、负值或超出约定范围 | 不显示异常值，进入不可用状态 | 不显示异常值，进入不可用状态 |

任何错误都只能安静降级；仪表端不得出现 Toast、对话框、日志、堆栈或重复闪烁提示。

## 投送与区域映射

Display ID 是整路投送通道的标识，不是照片中某个控件的 Android `viewId`。当前仪表最终画面不在普通 Android View 层中，因此无法从 `uiautomator` 或资源表直接取得“速度表 ID”和“音乐列表 ID”。

实现前应在停车状态完成以下映射验证：

1. 恢复 ADB，并确认 `adb devices -l` 为 `device`。
2. 向 Display 10 投送带透明背景的静态测试标记，记录它出现在左侧、右侧、全屏或完全不可见。
3. 清除 Display 10 测试标记，确认原车仪表完整恢复。
4. 对 Display 11 重复相同测试。
5. 记录左右映射、裁切比例、缩放方式和 Alpha 支持情况。
6. 只有当原车底层内容仍然可见时，才允许进入区域坐标标定。

验证记录采用下表，测试完成后填写真实结果并固化为设备配置：

| 通道 | 已知参数 | 验证结果的记录要求 |
|---|---|---|
| Display 10 | 1920×720、外部显示、ON | 记录物理区域、裁切矩形、透明度、旋转和恢复结果 |
| Display 11 | 1920×720、外部显示、ON | 记录物理区域、裁切矩形、透明度、旋转和恢复结果 |
| Display 3 | 520×280 私有地图/HUD 通道 | 明确排除，不执行转速投送测试 |

不得使用“创建一个新的动态虚拟显示”来替代 Display 10/11 映射验证，因为动态 ID 不保证连接到照片中的任何一个区域。

## 推荐实现顺序

1. 完成 Display 10/11 与左右区域的可见性和透明合成验证。
2. 先实现右侧功能卡片静态原型，验证转速卡片能沿用现有切换逻辑，并且不会影响音乐、车辆属性和行程数据。
3. 接入现有 APVP 转速数据，完成正常、暂停、不可用和发动机停止四种状态。
4. 在停车状态验证日间、夜间、不同主题及系统重启后的恢复行为。
5. 右侧方案稳定后，再评估左侧透明紧凑读数；未满足安全条件则不实现左侧方案。

右侧方案必须作为现有多功能卡片中的新增一项，而不是长期覆盖多功能区域。左侧方案必须严格追加在速度/功率纵向结构的最底部。两个方案统一使用 `1.0 × 1000 RPM` 格式。

## 验收标准

- APK 设置中只能选中 `关闭`、`左侧速度区`、`右侧转速卡片` 三者之一，不能同时选中左右位置。
- 左右位置切换时旧位置先消失，新位置才出现；异常或失败时回退到 `关闭`。
- 原车车速、挡位、警告灯、续航、油量和电量始终完整可见。
- 转速从有效数据到画面变化的总延迟不高于 300 ms。
- 正常刷新时无闪烁、跳帧、布局抖动和高频颜色跳变。
- 左侧原有“车速在上、功率在下”的结构、位置和尺寸保持不变，转速只出现在区域最底部。
- 右侧只有切换到转速卡片时才显示转速数值，切换到音乐、车辆属性或行程数据后不得残留。
- 两个区域都不得出现圆盘、指针、刻度、色带、进度条、曲线或启动扫表动画。
- 两个区域的转速格式必须为 `一位小数 × 1000 RPM`；1000 RPM 的验收画面应为 `1.0 × 1000 RPM`。
- 数据断开后 500 ms 内进入暂停表现，2 s 后进入不可用表现。
- 应用退出、崩溃、ADB 断开或车机重启后，原车仪表能够自动完整恢复。
- 日间和夜间主题下主数字对比度达到 7:1，辅助文字至少达到 4.5:1。
- 行驶过程中不要求触摸车机，不显示调试信息，不产生遮挡式错误提示。
- Display 10/11 的左右映射与裁切参数通过实车照片或视频留档后，才允许写入生产配置。
